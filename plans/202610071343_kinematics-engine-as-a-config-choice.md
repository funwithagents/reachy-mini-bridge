# The kinematics engine as a config choice, a `placo` extra, and a live sim tier per engine

**Status:** Done

Implements the settled behavior in `specs/core/config.md` ("`daemon` block", "Kinematics engines"), `specs/daemon/daemon.md` ("The launch command": the engine flag), `specs/core/bridge.md` ("Motors": the guard's message), `specs/project.md` (the `placo` extra, the `dev` group), `specs/testing/testing.md` ("One engine per run"), `specs/testing/testing_support.md` ("Configuration via the environment": `REACHY_MINI_E2E_KINEMATICS`) and `specs/testing/ci.md` (one live entry per engine). It delivers `daemon.kinematics_engine` (`analytical` default | `placo` | `nn`) passed as `--kinematics-engine` to every daemon the bridge spawns, sim and real alike, a `reachy-mini-bridge[placo]` extra carried by the `dev` group, the live tier runnable on each engine with a check that the daemon runs the one asked for, and a three-entry CI matrix. It deliberately leaves out `check_collision` (Placo-only collision checking; `config.md` open question), any change to the fake (it reports `Placo` on its daemon-client stand-in, which the guard tests flip), and the gravity-compensation probe (a Placo sim stays excluded, by design). Once this plan is `Done`, delete the untracked `analysis/kinematics-engine.md`.

Decisions made while writing the specs, beyond the analysis: the missing `placo` package is a `DaemonError` at launch (`launch_command`), not a `ConfigError` at load — a config for a borrowed daemon loads without the package, and it is the same shape as the missing-sim-extra error; the flag is always explicit (`--kinematics-engine AnalyticalKinematics` by default), like the preload flag; the engine check in the live tier fails on a mismatch and never skips.

## Steps

1. **The extra and the lock.** Add `placo = ["reachy-mini[placo_kinematics]"]` under `[project.optional-dependencies]` with a comment in the file's style (what it is, the engine it enables, no effect until a config asks); add `"reachy-mini-bridge[placo]"` to the `dev` group with its reason. `uv lock`, then `uv sync` and check `python -c "import placo"` works on the Mac. Check the lock resolves for Linux x86_64 (the runner) — `uv lock` is universal, so the wheel markers are in it; if `placo` has no wheel for a platform the lock covers, note it in `project.md`'s extra bullet.
2. **The config field.** In `config.py`: `KINEMATICS_ENGINES = ("analytical", "placo", "nn")` and `UPSTREAM_KINEMATICS_ENGINES = {"analytical": "AnalyticalKinematics", "placo": "Placo", "nn": "NN"}` next to `SPAWN_MODES`; `DaemonConfig.kinematics_engine: str = "analytical"`; accept the key in `from_dict`, reject anything not in the tuple with `ConfigError("'daemon.kinematics_engine' must be one of ..., got ...")`. Docstring: a daemon-launch knob applying to `sim` and `real` alike. Tests in `tests/test_config.py`.
3. **The launch command.** In `daemon.py`: a `_engine_flags(config)` returning `["--kinematics-engine", UPSTREAM_KINEMATICS_ENGINES[config.kinematics_engine]]`, appended right after `_preload_flag` on every recipe (headless, viewer, scene file, real). Before building a command whose engine is `placo`, `_placo_available()` false → `DaemonError("the daemon's Placo kinematics engine needs the placo package — install the placo extra (reachy-mini-bridge[placo])")`. Delete the real recipe's `if _placo_available(): cmd += [...]`. Update the module and `launch_command` docstrings. Rewrite `test_launch_command_real_robot`'s parametrisation (config → flags, the three engines), add the engine flag to every sim expectation in `tests/test_daemon.py` (the headless, viewer, scene and address tests), and add the two `DaemonError` tests (sim and real) asserting the message names the extra and that `managed_daemon` spawns nothing on that path.
4. **The guard's message.** In `bridge.py`: replace `_GRAVITY_COMPENSATION_ENGINE` by `UPSTREAM_KINEMATICS_ENGINES["placo"]` (imported from `config`); the message becomes: gravity compensation needs the daemon's Placo kinematics engine, but it runs `<engine>`; for a daemon the bridge spawns set `daemon.kinematics_engine` to `"placo"` (the `reachy-mini-bridge[placo]` extra), for one started by hand pass `--kinematics-engine Placo`; nothing was sent. Update the `set_motors_state` docstring and the two assertions in `tests/test_bridge.py` (`"daemon.kinematics_engine"` and `"--kinematics-engine Placo"` both in the message).
5. **The harness switch.** In `testing/_daemon.py`: `kinematics_engine()` reads `REACHY_MINI_E2E_KINEMATICS`, strips and lowercases, defaults to `"analytical"`, and `pytest.fail`s (never skips) on a word outside `KINEMATICS_ENGINES`, naming the three; both `DaemonConfig(...)` constructions in `managed_daemon` take `kinematics_engine=kinematics_engine()`. Module docstring. Tests in `tests/test_testing_support.py` through `monkeypatch.setenv`, with the fail asserted through `pytest.raises(pytest.fail.Exception)`.
6. **The engine check.** In `tests-e2e/test_motion.py`, `test_daemon_runs_the_engine_the_run_asked_for(live_bridge)`: `requires_caps(live_bridge, "motion")`; `engine = _daemon_kinematics_engine(bridge.robot)` run off the loop (`asyncio.to_thread` through `live_bridge.run`, or directly — it is blocking and side-effect-free); assert it equals `UPSTREAM_KINEMATICS_ENGINES[kinematics_engine()]` with a message saying a borrowed daemon runs another engine and to set `REACHY_MINI_E2E_KINEMATICS` to match. The reader is `reachy_mini_bridge.bridge._daemon_kinematics_engine`, which the harness's probe already imports; the switch is `reachy_mini_bridge.testing._daemon.kinematics_engine` (the bridge's own tier may import its private glue). Update the file's docstring.
7. **Run each engine locally, headless** (motion and audio): `uv run pytest tests-e2e -rs`, then with `REACHY_MINI_E2E_KINEMATICS=placo`, then `nn`. Read the skips; every file passes on all three or the failure is a finding (step 9).
8. **Run Placo and NN on the viewer sim** (the camera, the emotions, the gaze and tracking tests — the poses that meet the limits): `REACHY_MINI_E2E_SIM_VIEWER=1 REACHY_MINI_E2E_KINEMATICS=placo uv run pytest tests-e2e -rs`, then `nn`. Watch the daemon's log for `head pose not achievable` (the harness forwards it as a warning) and the motion loop's warnings; compare the tracking tests' settle times and the emotion tests' timings against the analytical run.
9. **Checkpoint.** If a Placo run rejects a target (a breath, an aim, an emotion outside the 35° cone or 55° relative yaw) or NN misses a convergence threshold: record the move and the measurement in `config.md`'s open question and in `testing.md` "One engine per run", and decide with the user whether the bridge's amplitudes change, the test adapts, or the engine is documented as rejecting that move — before the CI step lands. If every run is green, close the open question with the measurement (which moves ran, the tracking settle times per engine).
10. **CI.** (Outcome of step 9: NN over-rotates by 3 to 4° at 18° of yaw and fails two tracking tests on the centring check, so the matrix is `analytical` and `placo`; NN stays an accepted value with its error documented.) `e2e-sim` gets `strategy: { fail-fast: false, matrix: { kinematics: [analytical, placo] } }`, `name: live tier, headless sim (${{ matrix.kinematics }})`, and `REACHY_MINI_E2E_KINEMATICS: ${{ matrix.kinematics }}` in the live step's env; the workflow's header comment says why three. Push on a branch, watch the three entries (`gh run watch` in the background); read each entry's skips against `ci.md`'s table — the `gravity_compensation` skip appears on all three. Update the repository's required status checks to the three entries.
11. **Gravity compensation on the robot.** With the Lite on USB: `REACHY_MINI_E2E_TARGET=real REACHY_MINI_E2E_KINEMATICS=placo uv run pytest tests-e2e/test_motors.py -rs` — the gravity test runs and passes, the refusal test skips; then the default `REACHY_MINI_E2E_TARGET=real` run — the gravity test skips, the refusal test runs and passes. 12. **Docs and example config.** Every file in Scope under `docs/`, `config.example.json`, `README.md`, `AGENTS.md`, `examples/configs/README.md`; `tests/test_docs_consistency.py` enforces the field in `config.example.json` and `configuration.md`.
