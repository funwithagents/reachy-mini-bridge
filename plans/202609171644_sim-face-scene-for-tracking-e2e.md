# Sim face scene for tracking / attention e2e tests

**Status:** Done

Implements [specs/sim_scene.md](../specs/sim_scene.md): a hidden-by-default portrait plane in the bridge's shipped test scene that the bridge can show, place, move and hide while the daemon runs, so the viewer-sim e2e tier exercises face tracking, the attention hand-back and breathing-when-alone through the daemon's real detection pipeline. Ships in `reachy_mini_bridge.testing` (test-support tooling, not core), alongside the bundled portrait asset. Leaves out the spec's deferrals (headless EGL rendering, an upstream `--scene-path`, multiple prop shapes beyond the portrait plane, reporting the findings upstream).

## Scope

- `src/reachy_mini_bridge/testing/sim_scene.py` — new: `FacePlane` (`visible: bool = False` by default) / `write_test_scene` (scene generator; the generated floor is non-reflective, `reflectance="0"`), `upstream_scene_name`, `SceneDirector` (MuJoCo control-callback driver for mocap bodies, seeding initial `visible` from each body's compiled geom alpha), `build_router` (FastAPI `/api/sim-scene`), `directed_backend` / `run_daemon` (the `python -m` launcher wrapping upstream's `main`, installing the director once the model is built and stepping daemon-side head tracking each control tick), `SimSceneClient`, `BodyState`
- `src/reachy_mini_bridge/testing/assets/face.png` + `ATTRIBUTION.md` — the bundled public-domain portrait (NASA, via Wikimedia Commons)
- `src/reachy_mini_bridge/errors.py` — `SimSceneError`
- `src/reachy_mini_bridge/daemon.py` — `launch_command`: a `scene` ending in `.xml` runs the bridge launcher (mjpython for the viewer, this interpreter headless)
- `src/reachy_mini_bridge/testing/_daemon.py` — `REACHY_MINI_E2E_SIM_SCENE` (`test` generated into a temp dir for the daemon's lifetime); `testing/fixtures.py` — `faces` capability probe, `sim_scene` fixture
- `tests/test_sim_scene.py` — scene geometry against the eye camera (including the hidden-by-default alpha and the floor's zero reflectance), director through `mj_step`, router + client over a throwaway uvicorn, launcher argv/wrapping, the backend subclass's model-load-order fix and tracking step
- `tests/test_daemon.py`, `tests/test_testing_support.py` — the new recipe and harness knobs
- `tests-e2e/test_faces.py` — three live scenarios asserting *reaction*, not precise convergence (see "Tracking convergence" below): a face appearing, the attention hand-back with breathing, an emotion over tracking
- Specs/docs: `specs/sim_scene.md` (new) + index row; `daemon.md`, `config.md`, `testing.md`, `testing_support.md`, `_overview.md`; `AGENTS.md` map + e2e table; `README.md`; `docs/running-the-sim-daemon.md`, `docs/testing-with-the-bridge.md`

## Steps

1. Spike (scratch, no repo code): confirm upstream's YuNet fires on the bundled portrait pasted into a downscaled 720p frame (from ~40 px of portrait height), then on a frame *rendered* from the eye camera with the photo textured onto a mocap plane at the default pose, left, right, 0.3 m and 0.7 m; confirm alpha 0 hides it. Fix the plane orientation (`FACE_QUAT`) from the render.
2. Write `sim_scene.py`: generator (absolute include/meshdir/texture paths, one mocap body + emissive textured box per prop, an explicit `rgba` alpha of 0 or 1 from each prop's `visible`), `upstream_scene_name` (relative to upstream's `scenes/`), the director (attach on first callback — seeding `visible` per body from its compiled geom alpha — wall-clock lerp from the current interpolated pose, alpha visibility, change-skipping writes, exception guard), the router (GET/POST, 404/400), `run_daemon` (argparse with passthrough, `directed_backend` substituted into `reachy_mini.daemon.daemon` so the callback is installed *after* the model is built — a callback present during the load makes `MjModel.from_xml_path` fail — and stepping `step_head_tracking()` on each control tick, which upstream's MuJoCo loop never does — `create_app` wrap, `sys.argv` rewrite, upstream `main()`), the urllib client with `SimSceneError` mapping (a 404 without "unknown body" means no endpoint).
3. Move the module and the bundled asset into `reachy_mini_bridge.testing` (they are test-support tooling, not core), and default `FacePlane` to `visible=False` so the generated scene loads with nothing in view until a test asks for it.
4. Route `.xml` scenes in `daemon.launch_command`; add `SimSceneError`.
5. Harness: `sim_scene()` env read (`test` sentinel), `_resolved_sim_scene` context (temp dir for the daemon's lifetime), `_probe_faces` folded into `_probe_capabilities(robot, address)`, the `sim_scene` fixture.
6. Fast tests: load the generated scene in MuJoCo (mocap face inside the eye camera frustum, facing −x, upright, hidden by default), multi-plane/custom image/per-prop visibility, bad inputs, `upstream_scene_name` round trip, director through real `mj_step`s with a fake clock (move, retarget, hide/show), command validation, `BodyState` round trip, client ↔ router over uvicorn (place/wait/hide/errors, no-endpoint, unreachable), launcher argv + mounted routes + the backend subclass's model-load-order behaviour and tracking step, missing scene; `launch_command` recipes; harness env/scene/probe tests.
7. Live investigation on the viewer sim (with a person watching): a reflective checker floor (upstream's own material, `reflectance="0.2"`) produces a mirrored, upside-down reflection of the face plane that the detector locks onto as readily as the real face — captured on a live frame, fixed by zeroing the generated floor's reflectance. With that fixed, tracking still doesn't visually *converge* on the target: a cold `start_head_tracking()` reliably overshoots (30–45°, holds there) and the attention hand-back's own `watching → engaged` restore reliably under-reacts (settles a few degrees off, regardless of the target's actual position) — confirmed as a genuine control-loop characteristic of upstream's tracking algorithm under the sim's timing (not a geometry or intrinsics bug: correcting `MujocoCameraSpecs.K`'s field-of-view mismatch, also found and confirmed live, made the oscillation worse, so that correction is not applied — see specs/sim_scene.md "Tracking convergence"). `tests-e2e/test_faces.py` is designed around this: it asserts a large, easily-thresholded reaction and the correct attention *state* transitions, never a precisely converged angle.
8. E2E tests on the test scene, gated on `camera` + `faces`, each test re-arming tracking at its start (`stop_head_tracking()` / `start_head_tracking()`) so the module-scoped `live_api` session's attention grace timer starts fresh per test.
9. Docs and statuses; project map row; run the gate.
