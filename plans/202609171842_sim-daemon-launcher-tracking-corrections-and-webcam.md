# Sim daemon launcher: tracking corrections for every sim, and a webcam camera source

**Status:** Done

Implements [specs/sim_daemon.md](../specs/sim_daemon.md) and the changes it drives in [specs/daemon.md](../specs/daemon.md) ("The launch command"), [specs/config.md](../specs/config.md) (`daemon.camera`) and [specs/sim_scene.md](../specs/sim_scene.md) ("Head tracking converges on the face"). Delivers a core `reachy_mini_bridge.sim_daemon` launcher that every bridge-spawned sim runs through — tracking stepped on each control tick, the tracker's intrinsics corrected, and a `webcam` camera source with fixed-camera tracking geometry — rebuilds the test scene's launcher as an extension of it, and tightens the face e2e tests from "the head reacted" to "the head converged". Leaves out the spec's deferrals: webcam calibration, correcting the intrinsics the daemon reports to clients, non-720p webcams, and reporting the corrections upstream.

## Background (the investigation this plan rests on)

Upstream's MuJoCo backend never calls `step_head_tracking()`, and the face tracker scales `MujocoCameraSpecs.K` (a 1280×720 matrix) as if calibrated at 3840×2592, giving fx 106.7 / fy 50 / principal point (53.3, 25) at 320×180 instead of f 107.3 / (160, 90). The head converges ~45° off the face; re-engaged from the attention loop's watch weight, IK fails every tick and it freezes. Verified in an offline closed-loop replica (real backend, render, YuNet) and live on the viewer daemon: with pinhole intrinsics from the eye camera's `fovy` the head settles at yaw 0° / ±19–20° for a face ahead / ±0.15 m, the face at the image centre, re-engage included. Replaces the "control-loop lag" explanation previously in `specs/sim_scene.md`.

## Steps

1. **Config.** `SimCameraSettings` with the validation rules of config.md (source ∈ {sim, webcam}; device null / non-empty string / non-negative non-bool int; `hfov_deg` non-bool number in (1, 179); unknown keys refused); `DaemonConfig.camera` parsed from the `camera` object, default `SimCameraSettings()`. Update `config.example.json`. Tests: defaults, a full webcam block round-trips, each invalid value/key is a `ConfigError` naming it.
2. **Intrinsics.** `pinhole_intrinsics(hfov_deg, (w, h))` → `[[f,0,w/2],[0,f,h/2],[0,0,1]]`, `f = (w/2)/tan(hfov/2)`; `sim_hfov_deg(fovy_deg, w, h) = 2·atan(tan(fovy/2)·w/h)`. The launcher installs a replacement for `reachy_mini.vision.face_tracking.intrinsics_for_size` whose field of view is read at call time from launcher state set by the backend's `__init__` (`sim`: `model.cam_fovy[eye_camera]`; `webcam`: `--webcam-hfov`) — the tracker computes its matrix when its thread first sees a frame, after the backend exists. Leave `reachy_mini.media.camera_utils.intrinsics_for_size` untouched.
3. **Backend subclass** (`corrected_backend`): `__init__` calls super, records the camera field of view, then each extension's `on_backend(self)`. `update_head_kinematics_model` → super, then `step_head_tracking()` (moved from sim_scene). For `webcam`: `set_tracking_face` sets a thread-local flag around `super().set_tracking_face(...)` and `get_current_head_pose` returns `INIT_HEAD_POSE.copy()` while the flag is set (every other caller, on any thread, sees the real pose); `rendering_loop` returns at once; `run` starts the `WebcamRelay` before `super().run()` and stops it after.
4. **Webcam relay.** A GStreamer pipeline in its own thread: source (`autovideosrc`; `avfvideosrc device-index=N` on macOS for an int; `v4l2src device=PATH` on Linux for a string) → `video/x-raw,width=1280,height=720` → `videoconvert` → `video/x-raw,format=RGB,width=1280,height=720` → `rtpvrawpay mtu=1400` → `application/x-rtp,payload=96` → `udpsink host=127.0.0.1 port=5005 sync=false` — the caps upstream's `GStreamerUDPCamera` sends and `GstMediaServer._build_sim_source` expects. A buffer probe timestamps the last frame; a failed state change, a bus error, or no frame for 5 s logs one `ERROR` (device, and on macOS the camera-permission hint naming the launching app) and retries every 5 s, logging again only after a success. Pipeline construction behind a module-private seam so tests run without a camera.
5. **Launcher.** `run_sim_daemon(argv, *, extensions=())`: argparse `--scene`, `--headless`, `--[no-]preload-datasets`, `--camera {sim,webcam}`, `--webcam-device` (int when it parses as one), `--webcam-hfov` (default 70); `parser.error` for webcam flags without `--camera webcam`; substitute `reachy_mini.daemon.daemon.MujocoBackend`; wrap `reachy_mini.daemon.app.main.create_app` to call each `on_app(app)`; install the intrinsics replacement; rewrite `sys.argv` (`--sim [--scene] [--headless] --[no-]preload-datasets` + passthrough); call upstream `main()`. `python -m reachy_mini_bridge.sim_daemon` runs it.
6. **Test scene on top.** `scene_extension(director)` → `SimDaemonExtension(on_backend=install director via mujoco.set_mjcb_control, on_app=include_router)`; `run_daemon` parses `--scene-path` (existence check as today), converts with `upstream_scene_name`, and calls `run_sim_daemon(["--scene", name, *rest], extensions=[scene_extension(director)])`. Delete `directed_backend`.
7. **Launch recipes.** `launch_command` for `sim`: `.xml` scene → the scene launcher as today; otherwise `[sys.executable, "-m", "reachy_mini_bridge.sim_daemon", "--headless", ...]` headless and `[mjpython, "-m", "reachy_mini_bridge.sim_daemon", ...]` viewer; both append `--camera webcam [--webcam-device D] --webcam-hfov H` when `config.camera.source == "webcam"`; `reachy-mini-daemon` on `PATH` still required as the sim-extra check. `real` unchanged. Tests: every combination's argv, and the missing-launcher errors.
8. **Fast convergence tests** (`tests/test_sim_daemon.py`, `pytest.importorskip("mujoco")`): build the corrected backend on `write_test_scene(tmp, faces=(FacePlane(visible=True, pos=P),))` headless without running the daemon; install a stand-in tracker whose `latest()` returns an observation computed each tick by projecting the face body's position through the eye camera (`data.cam_xpos` / `cam_xmat`, MuJoCo's −z optical axis, y up → image rows down) into a 320×180 frame with the true pinhole — the matrix passed in the observation being what the launcher's `intrinsics_for_size` returns; tick 10 `mj_step`s + kinematics update (which steps tracking) + IK + ctrl for ~4 s of sim time. Assert the optical axis ends within 3° of the face for P ahead and ±0.15 m; with the matrix upstream's `intrinsics_for_size` gives, assert it ends more than 30° off. Fixed camera: a constant observation at normalised (0.5, 0) — `webcam` geometry settles at the yaw `look_at_image_pose` gives from the neutral pose and moves less than 1° over the last second; head-mounted geometry exceeds that yaw by more than 15°. Plus: intrinsics equal the pinhole for both sources at 320×180 and 1280×720; a tick calls tracking after the kinematics update; `on_backend` runs after the model exists and `on_app` on the built app; argv rewriting and webcam-flag errors; in `webcam` mode `rendering_loop` returns immediately and the relay starts/stops with `run` (seam-faked); the relay's watchdog logs once and retries on a fake pipeline that never produces a frame.
9. **Scene tests.** Move the launcher tests in `tests/test_sim_scene.py` onto `run_daemon` → `run_sim_daemon` with the extension (argv, mounted routes, director installed once the model exists); drop the moved tracking-step test.
10. **E2E.** `tests-e2e/test_faces.py`: settle helper (poll head yaw/pitch until stable, bounded); assert yaw within ±5° of `degrees(atan2(y, 0.45 − 0.04))` for faces ahead and at ±0.15 m and `get_tracked_face()` |x|, |y| < 0.1; hand-back → `watching`, neutral, breathing (as today); face shown at the opposite side → `engaged` and yaw converges on the new position; emotion over tracking → after it, converges on the still-visible face. Rewrite the module docstring (no "reaction, not precision" caveat).
11. **Docs, map, frontmatter, statuses** per Scope.
12. **Gate**, then the live checks below.
